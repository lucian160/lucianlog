How to use Lucian Logs

Lucian Logs helps developers capture application activity, inspect logs, and understand errors from one place. This page explains the setup flow and the basic usage model for new users.

Overview

Lucian Logs is a simple monitoring platform for collecting and searching application logs. The main workflow is: create an account, create a project, generate an API key, send logs from your app, and then view the results in the dashboard.

Each project represents an application or service you want to track. Logs are organized by project and can be filtered by message, status code, level, endpoint, or other useful metadata.

Install

Run the following commands in the project folder:

npm install
cp .env.example .env

Then update the values in .env for your MongoDB URL and other required settings.

Configure the environment

Minimum settings usually include:

  • PORT — the server port
  • MONGO_URI — the MongoDB connection string
  • JWT_SECRET — your secure secret for authentication
  • CORS_ORIGIN — the allowed frontend origin

Optional settings include email delivery through Resend, firewall rules, and monitoring configuration. 

PORT=5000
MONGO_URI=mongodb://localhost:27017/lucianlogs
JWT_SECRET=replace_with_a_secure_secret
CORS_ORIGIN=http://localhost:5000

Project flow

The typical flow looks like this:

  1. Create an account and verify your email.
  2. Create a project from the dashboard.
  3. Copy the generated project API key.
  4. Use that key in your app to submit log data.
  5. Open the dashboard and inspect errors, warnings, and recent activity.

Keep the project API key private. It should not be placed in public frontend code or a public repository.

Send logs from your app

Logs are sent to the API using the project API key in the request header:

fetch("/api/logs", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-api-key": "YOUR_PROJECT_API_KEY"
  },
  body: JSON.stringify({
    level: "error",
    message: "Payment request failed",
    statusCode: 500,
    endpoint: "/api/payments",
    method: "POST"
  })
});

This makes Lucian Logs a place where your app can send operational information, errors, and important events for tracking.

Use the dashboard

The dashboard provides access to:

  • Project activity
  • Recent log entries
  • Error and warning summaries
  • Search and filtering tools
  • Project and user management

You can search by message, endpoint, method, log level, or HTTP status to investigate an issue faster.

Monitoring and uptime

Lucian Logs also exposes a health endpoint so monitoring tools such as UptimeRobot can check that the service is running. 

http://localhost:5000/health

This endpoint returns a simple JSON response with the application status and timestamp, making it easy to verify that the app is online.

Frequently asked questions

  • Do I need MongoDB? Yes. Lucian Logs stores project and log data in MongoDB.
  • Can I use this without email setup? Yes, but email verification and password reset may print OTP codes in the server terminal instead of sending them.
  • Where do I send logs from? Use the project API key and send requests to the log API endpoint.
  • What is the health endpoint used for? It lets uptime and monitoring tools confirm that your app is still online.
