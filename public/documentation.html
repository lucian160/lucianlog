Start here

Lucian Logs has two connected parts. The website is where you create projects and investigate logs. The API is where your application sends log events.

  1. Create your account and verify your email.
  2. Log in and create a project for the application you want to monitor.
  3. Copy the project API key.
  4. Configure your application to send logs with that key.
  5. Return to the dashboard to search and investigate the logs.

Account and project

Your Lucian Logs account is for people. Use your email and password to sign in to the website.

A project represents one application or service. Each project has its own API key and its own logs.

The API key is shown when a project is created. You can generate a replacement key from the API Keys page, but the old key stops working immediately.

Connect an application

You do not need to install an SDK or package. Your server sends a normal HTTPS request to the Lucian Logs API.

Store the project API key as a server-side environment variable. Do not put it in browser JavaScript, mobile app code, screenshots, or public repositories.

Send logs from your app

Send a POST request to /api/logs. Put the project key in the x-api-key header.

fetch("/api/logs", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-api-key": "YOUR_PROJECT_API_KEY"
  },
  body: JSON.stringify({
    level: "error",
    message: "Payment request failed",
    statusCode: 500,
    endpoint: "/api/payments",
    method: "POST"
  })
});

A successful request returns 201. The log is saved under the project connected to that API key.

Only send logs from your server. If the firewall is enabled for your deployment, your server must also send the configured approval header.

View and investigate logs

Log in to the website, select the project, and open Dashboard or Logs. New logs appear there automatically after the API accepts them.

  • Use Dashboard for totals, error rates, warnings, and the latest activity.
  • Use Logs to search by message, endpoint, method, level, or status code.
  • Use the project API key only for sending logs; your account login is used to view them.

Security and firewall

Account passwords and dashboard access use your verified account login. Application log submissions use the project API key. These are separate credentials.

Use HTTPS in production and keep API keys private. Rate limiting and payload validation protect the API from accidental or abusive traffic.

The firewall is an additional restriction for trusted deployments. IP allowlists are best for fixed servers; they are not a reliable identity check for people whose home or mobile IP changes.

Questions

  • Do I need to install anything? No SDK or package is required. Send JSON over HTTPS.
  • Why are my logs not visible? Confirm that the request returned 201, that the API key belongs to the selected project, and that you are viewing that same project.
  • Can I use one key for multiple apps? You can, but separate projects and keys make investigations clearer and limit the impact of a leaked key.
